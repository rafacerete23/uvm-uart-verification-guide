0 Electricidad básica Básico

Todo sistema digital se basa en voltaje, corriente y resistencia. Comprender la Ley de Ohm es el primer paso para entender por qué un UART transmite niveles de tensión.

Conceptos clave

Voltaje (V) – diferencia de potencial eléctrico.
Corriente (I) – flujo de carga por unidad de tiempo.
Resistencia (R) – oposición al flujo de corriente.
Ley de Ohm: V = I × R
Divisor de tensión: Vout = Vin × R2 / (R1 + R2)

Corriente: 5.00 mA
Vout: 2.20 V

Niveles lógicos y level shifting

Los microcontroladores usan niveles como 3.3V, 5V o 1.8V para representar 0 y 1. Conectar dos sistemas con voltajes diferentes requiere adaptar niveles. Un divisor resistivo es la técnica más sencilla para bajar de 5V a 3.3V.

Ejemplo: 5V → divisor 1k/2k → 3.3V.

1 Comunicación serie Básico

Una comunicación serie envía los bits uno tras otro por un solo cable de datos. Es más lenta que la paralela, pero usa menos pines y funciona bien a largas distancias.

Serie vs paralelo

Serie: 1 cable de datos, 1 bit a la vez.
Paralelo: 8+ cables, 8 bits simultáneos.

Conceptos UART

Idle (reposo): línea alta 1.
Baudrate: bits por segundo (p. ej. 9600).
RS-232 usa voltajes ±12V, UART TTL usa 3.3V/5V.

Ruido y masa común

Una masa común es esencial. Sin ella, los niveles de referencia difieren y la comunicación falla.

2 Lógica secuencial y contadores Intermedio

Para generar los tiempos de bit necesitamos dividir el reloj. Un flip-flop almacena un bit en cada flanco activo. Contadores encadenados dividen la frecuencia.

Parámetro CLKS_PER_BIT

CLKS_PER_BIT = f_clk / baudrate. Por ejemplo, con un reloj de 16 MHz y baudrate 1 Mbps, CLKS_PER_BIT = 16.

El redondeo introduce error. La calculadora muestra el error porcentual.

Divisor: 1666.67 → error: -0.01%

Máquinas de estados (FSM)

El transmisor y receptor del UART son FSMs: IDLE → START → DATA → STOP → IDLE. Cada estado consume exactamente CLKS_PER_BIT ciclos de reloj.

3 La trama UART 8N1 Intermedio

La trama 8N1 consta de 1 bit de inicio (0), 8 bits de datos LSB primero y 1 bit de stop (1). El receptor muestrea en el punto medio de cada bit para máxima inmunidad al ruido.

El siguiente código es el corazón del DUT del repositorio:

module uart_core #(
  parameter int CLKS_PER_BIT = 16
) (
  input  logic clk, rst_n,
  input  logic [7:0] tx_data,
  input  logic tx_valid, output logic tx_ready, txd,
  input  logic rxd, output logic [7:0] rx_data,
  output logic rx_valid, rx_frame_err
);
  // Transmisor: TX_IDLE → TX_START → TX_DATA → TX_STOP
  // Receptor: doble flip-flop en rxd, muestreo medio de bit,
  // recuperación tras error de trama esperando línea alta.

Prueba el simulador interactivo. Escribe un byte en hex o un carácter ASCII, elige CLKS_PER_BIT y pulsa Play.

Comportamiento del receptor

  • Sincronización doble flip-flop en rxd para evitar metaestabilidad.
  • Detecta flanco bajo en rxd_s2 (2 ciclos de retraso).
  • Valida el bit de inicio muestreando a mitad del bit: si es alto, descarta como glitch.
  • Muestrea los 8 datos a mitad de bit, luego el stop. Si el stop es bajo, genera rx_frame_err y espera línea alta antes de buscar otra trama.

4 Verificación con UVM Avanzado

UVM organiza la verificación en capas: secuencias generan transacciones, drivers convierten en señales, monitores observan la interfaz, scoreboard compara, coverage mide.

Haz clic en un componente para ver el archivo correspondiente.

Estos son los archivos reales del testbench UVM

  • tb/uart_if.sv – interfaz con señales clk, rst_n, etc.
  • tb/uart_tx_driver.sv – entrega bytes al DUT cuando tx_ready alto.
  • tb/uart_rx_driver.sv – bit-banguea rxd con opciones bad_stop y glitch.

5 Cobertura y aserciones Avanzado

La cobertura funcional garantiza que probamos todos los casos interesantes. Las aserciones SVA validan protocolos en tiempo real.

Covergroups del testbench real

  • tx_data_cg: data patterns zero, FF, AA, 55, walking.
  • tx_gap_cg: gaps cortos y largos entre bytes.
  • tx_backtoback_cg: back-to-back con gap = 0.
  • rx_bad_stop_cg y rx_glitch_cg: errores inyectados.

Ejemplos de aserciones SVA

// 1: tx_ready solo cuando TX_IDLE
property tx_ready_idle;
  @(posedge clk) disable iff (!rst_n)
    (tx_ready) |-> (tx_state == TX_IDLE);
endproperty

// 2: tras tx_valid aceptado, txd baja en el siguiente ciclo
property start_bit_low;
  @(posedge clk) disable iff (!rst_n)
    (tx_valid && tx_ready) |=> (txd == 1'b0);
endproperty

// 3: rx_valid y rx_frame_err nunca simultáneos
property rx_exclusive;
  @(posedge clk) disable iff (!rst_n)
    !(rx_valid && rx_frame_err);
endproperty

// 4: tras rx_frame_err, el receptor entra en recuperación
property frame_err_recover;
  @(posedge clk) disable iff (!rst_n)
    (rx_frame_err) |-> (rx_state == RX_RECOVER);
endproperty

6 Nivel empresa Experto

En producción, la verificación es sistemática: regresiones con semillas, integración continua, checklist de sign-off y barridos de tolerancia.

Regresiones y CI

Se lanzan múltiples tests con diferentes semillas en cada push. Un fallo bloquea la fusión.

Sign-off checklist

Cobertura ≥ meta, no errores pendientes, regresión limpia, revisión por pares.

Prácticas de industria

Verificación basada en aserciones, verificación formal, constrained random, code review obligatorio.

Comparación: UART es asíncrono y punto a punto; SPI es síncrono maestra-esclava con líneas separadas; I2C usa dos cables con direccionamiento.
